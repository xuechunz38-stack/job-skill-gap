Important implementation decisions

* Matching: each skill gets one regex built from its aliases, longest alias first. Instead of \b, the regex uses custom "not next to a letter, digit or _" checks, so C++, .NET and Node.js match but Spark doesn't match inside PySpark. The matcher returns a set, so a skill counts at most once per posting.
* Order of steps in the CLI: it loads the dictionary, then the postings, then the resume, and only then creates the output folder. A failed run never leaves partial files.
* Exit codes: 1 for bad skills data; 2 for missing paths, an empty postings folder, usage errors, or an output folder that can't be created.
* Same results every run: the CSV uses \n line endings, fixed 3-decimal numbers and a full ranking sort. The ranking is count (highest first), then missing skills before owned ones, then name A–Z. A test checks that two runs give byte-identical files.
* Sample data: 8 synthetic postings that cover the planned edge cases. Posting 07 deliberately has no dictionary skills, so a sample run always shows that warning. The sample resume uses sklearn to show resume aliases working, and includes "Wind API", which isn't in the dictionary, to show the unknown-term warning.
* Chart: a single-color bar chart with the count on each bar. If nothing is missing, it still writes a placeholder chart saying "No missing skills found".

Deviations from the plan

1. analyze() takes raw resume terms (resume_terms), not an already-resolved owned: set[str]. Plan §6.4 needs unknown resume terms reported by analyze, which isn't possible if it only receives the resolved set. It now resolves the terms itself through resolve_resume().
2. AnalysisResult lives in models.py, next to the other dataclasses. Warnings come from a separate pure function, collect_warnings().
3. Postings loading is a bit more lenient: .TXT files are accepted, and hidden files like macOS ._foo.txt are skipped.
4. Skills CSV checks are a bit stricter: an extra column (usually a , typed where a | was meant) and an empty skill name are both errors. The header check ignores case and spaces.
5. The skills dictionary has 44 skills, not ~35. I needed the extra ones for the sample postings to give realistic results.
6. --quiet still prints warnings, to stderr.
7. The Makefile uses python3 by default. On macOS there's often no plain python command.

PYTHON  ?= python3

	$(PYTHON) -m pip install -e .
	$(PYTHON) -m pip install -r requirements-dev.txt

format:
	$(PYTHON) -m black $(SRC)

format-check:
	$(PYTHON) -m black --check --diff $(SRC)

lint:
	$(PYTHON) -m flake8 $(SRC)

test:
	$(PYTHON) -m pytest -v

# Optional: needs pytest-cov (in requirements-dev.txt). Not part of `all` or CI.
coverage:
	$(PYTHON) -m pytest -v --cov=job_skill_gap --cov-report=term-missing

run:
	$(PYTHON) -m job_skill_gap \
		--postings $(SAMPLE)/postings \
		--skills $(SAMPLE)/skills.csv \
		--resume $(SAMPLE)/resume_skills.txt \
		--out-dir $(OUT_DIR)

docker-build:
	docker build -t $(IMAGE) .

docker-run:
	docker compose run --rm job-skill-gap

clean:
	rm -rf build dist *.egg-info src/*.egg-info .pytest_cache .coverage htmlcov
	find . -name __pycache__ -type d -prune -exec rm -rf {} +
	find $(OUT_DIR) -mindepth 1 ! -name .gitkeep -delete

all: format-check lint test
